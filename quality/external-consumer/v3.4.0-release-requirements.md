# NGB v3.4.0 release requirements

These requirements separate FULL Certification from the maintainer's manual
platform/application regression checks. Backend/Frontend suites and full coverage
are run independently, as explicitly directed by the maintainer. FULL Certification
also runs locally before every release. GitHub Actions builds and publishes NuGet/npm
packages and verifies their registry identities; it does not repeat tests, coverage,
certification or Codex/Claude evaluations and does not import local packages/reports.

The [AI Development Kit specification](../../ai-devkit/SPECIFICATION.md) defines
the Kit's public-SDK contract, independent examples and conformance evidence.
This document owns the additional platform and existing-application regression
requirements. Their coverage thresholds remain unchanged; they are outside both
the Kit and automatic FULL Certification.

## Scope and dependency direction

Manual regression covers the complete platform and its existing applications:

- Property Management.
- Trade.
- Agency Billing.
- CRM.

Keep this application inventory, project/host identities and product-specific
acceptance scenarios in platform/application regression. The release orchestrator
consumes Kit and external-consumer evidence; it does not run or import these
manual regression results. The Kit must not import this
inventory, require these applications to run its conformance suite, or package
their business definitions, reports, configuration, data or workflows as generic
SDK guidance.

Existing application workflows remain regression fixtures owned by their
applications and release verification. Kit examples are independently authored
consumers of public packages. Application-specific agent guidance belongs to the
respective application's custom content.

## Manual tests and full coverage

The maintainer runs Backend test projects directly, including platform MCP and
AI Assistant tests and the applications' API, Runtime, BackgroundJobs and Watchdog
tests. The maintainer also runs the existing Frontend and coverage commands:

```sh
npm --prefix ui run test:all
NGB_FRONTEND_COVERAGE_JOBS=3 ./run-frontend-full-coverage.sh
NGB_BACKEND_COVERAGE_JOBS=3 ./run-backend-full-coverage.sh
```

FULL Certification must not invoke these directly or through nested scripts,
including the platform framework browser matrix, `quality/mcp/verify-contract.mjs`
and `quality/mcp/verify-verticals.mjs`. It must not require manual reports as a
replacement gate. The standalone `run-full-quality.sh` aggregate remains available
for explicit manual use and is not part of `release.mjs certify`.

Backend coverage must be **100% lines, 100% branches and 100% methods** for all
applicable production C# code across Platform, Property Management, Trade,
Agency Billing and CRM. Frontend coverage must be **100% lines, 100% branches,
100% functions and 100% statements** across the shared UI and all four application
web projects.

Preserve strict per-file completeness and the existing narrowly documented,
auditable generated-code exemptions. New source files must appear in discovery
and coverage reports. Do not lower thresholds, hide sources, exclude reachable
production code, skip failing tests or alter metrics to make a gate pass.

Keep the existing verifiers authoritative:

- [Backend full coverage](../coverage/verify-backend-full-coverage.mjs).
- [Frontend full coverage](../coverage/verify-frontend-full-coverage.mjs).
- [Tooling quality inventory](quality-inventory.json).

Kit, template and executable-helper coverage remains independently required by
the Kit specification and applicable tooling policy. A Kit conformance pass does
not replace the complete platform/application coverage results.

## Application regression acceptance

Run the backend/frontend suites and actual API/worker host regressions of
Property Management, Trade, Agency Billing and CRM. Preserve existing public
workflows and use real provider/database integrations for migration and
persistence claims. Mocks are not evidence of successful real data migrations.

Verify document lifecycle, relationships, accounting, operational/reference
registers, reports, projections, background jobs and enabled integrations where
supported by the corresponding application. Preserve existing performance
baselines, volume regressions and required live-load profiles; record the actual
workloads, measurements and tolerances.

Keep authorization consistent between API and UI in all four applications:
active administrators receive all registered permissions, including Attachments,
Notes and newly registered capabilities. Verify both linked platform users and
trusted Keycloak `ngb-admin` identities without a pre-existing platform user.
Identify application administrator roles by registered codes rather than editable
display names. Feature flags remain independent and inactive accounts stay
blocked.

Preserve existing MCP/AI Assistant tests in the manual Backend regression,
including actual-host coverage. Certification retains the independent package-only
MCP consumer and external upgrade checks. Those adapters use existing
authorized application services; regression work does not authorize changes to
business logic, SQL readers, schemas, migrations, report calculations, domain
filters, business contracts or permission rules to make an assistant scenario
pass. Report unsupported scenarios for a separate explicit scope decision.

## Evidence and release readiness

The v3.4.0 release runner binds package identity, compatibility, external-consumer
profiles, tooling/performance checks and five Kit profiles to its candidate.
Its Linux tooling preflight uses `--certification --preflight` and records
`certification/quality-preflight.json` with hashes of the tooling and performance
reports. There is no subsequent platform browser, Backend or Frontend stage.
Certification does not require `full-quality.json` or full coverage reports.

The backend runsettings use VSTest `TreatNoTestsAsError` and xUnit `FailSkips` so
an empty suite or a skipped required test produces a failed process result.
See the [VSTest settings](https://learn.microsoft.com/en-us/visualstudio/test/configure-unit-tests-by-using-a-dot-runsettings-file)
and [xUnit RunSettings](https://xunit.net/docs/config-runsettings#FailSkips).

FULL Certification does not launch the platform's Ollama tests because it does
not run the platform Backend suite. To run the native tests manually, start
Ollama with the selected model and follow the
[local model test command](../../docs/guides/ai-assistant.md#verification).

Bind automatic Kit and external-consumer results to the exact candidate source tree,
NuGet/npm artifacts, lockfiles, toolchain, profiles and execution options. Include
the complete expected suite inventory, discovered tests, skipped/failed checks,
coverage source inventory, report hashes and measured performance results.
Invalidate evidence when its relevant inputs change. Keep offline tooling
checks, volume regressions and live-load results distinguishable.

The certification report includes Kit/tooling/helper and external-consumer results.
It must not claim that full platform/application tests or coverage were executed.
Manual coverage reports retain their actual measured results separately. Identify
each automatic gate and release stage, including compatibility, package identity,
publication and registry promotion.

Report a stage as **READY** only after every required check for that stage has
actually passed. Otherwise report **NOT READY** with actionable blockers. Missing
tools/services, skipped suites and absent evidence are not passes. Candidate
readiness does not imply verified publication or registry promotion. Preserve all
existing release/provenance gates and do not publish or merge with known red gates.
